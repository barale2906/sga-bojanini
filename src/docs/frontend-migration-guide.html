Guía de Migración Frontend — API Movimientos de Inventario

v2 · Julio 2026

Resumen ejecutivo

  • 2 endpoints rompen compatibilidad: POST /movements/exit (producto simple) y POST /movements/transfer. La clave data ahora es un array de movimientos, no un objeto.
  • Siempre array, incluso cuando FEFO selecciona un único lote. El array tendrá exactamente un elemento.
  • Múltiples elementos cuando el stock de un producto está repartido en más de un lote y FEFO consume de ambos.
  • Todo el resto del API (entradas, ajustes, devoluciones, bajas, listados) no cambia.
  • El exit de kit ya devolvía array desde antes — no cambia.

Cambios breaking

Endpoints con respuesta modificada

POST /api/v1/movements/exit Breaking change

Aplica a productos de tipo Simple. Cuando FEFO selecciona múltiples lotes para cubrir la cantidad solicitada, ahora se registra un movimiento independiente por cada lote afectado. La respuesta refleja ese cambio: data pasa de ser un objeto a un array.

Antes — objeto único
{
  "success": true,
  "message": "Salida registrada",
  "data": {
    "id": 42,
    "batch_id": 7,
    "batch_lot_number": "LOT-A",
    "quantity": -10,
    "movement_type": "exit",
    "cost_center_id": 3
  }
}
Ahora — array de movimientos
{
  "success": true,
  "message": "Salida registrada",
  "data": [
    {
      "id": 42,
      "batch_id": 7,
      "batch_lot_number": "LOT-A",
      "quantity": -8,
      "movement_type": "exit"
    },
    {
      "id": 43,
      "batch_id": 9,
      "batch_lot_number": "LOT-B",
      "quantity": -2,
      "movement_type": "exit"
    }
  ]
}
⚠
Ejemplo real: Si el usuario pide 10 unidades y el almacén tiene 8 en el Lote A (vence en 30 días) y 15 en el Lote B (vence en 90 días), FEFO toma 8 del A y 2 del B → se devuelven 2 movimientos, con quantity: -8 y quantity: -2 respectivamente. El total sigue siendo –10.
POST /api/v1/movements/transfer Breaking change

Los traslados entre almacenes aplican el mismo cambio: FEFO puede seleccionar múltiples lotes, y cada uno genera su propio registro. data pasa de objeto a array. El campo quantity en un traslado es positivo.

Antes — objeto único

  }
}
Ahora — array de movimientos
{
  "success": true,
  "data": [
    {
      "id": 55,
      "batch_id": 7,
      "batch_lot_number": "LOT-A",
      "quantity": 8,
      "warehouse_to_id": 2,

      "id": 56,

      "warehouse_to_id": 2,

POST /api/v1/movements/exit  — producto tipo Kit Sin cambios

La salida de kit ya devolvía un objeto con kit_transaction_id y un array de movements. Esta estructura no cambia. 

{
  "success": true,
  "data": {

}

Guía de adaptación

Cómo actualizar el código frontend

1

Locate all call sites de POST /movements/exit y POST /movements/transfer en el frontend y aplica el patrón de abajo.

2

Acción de éxito (mostrar toast, redirigir): no depende de data — response.success === true sigue siendo la señal. Sin cambios aquí.

3

Mostrar detalle post-operación: data es ahora un array. Si solo necesitas mostrar un ID o número de movimiento, usa data[0].id. Si quieres mostrar todos los lotes afectados, itera sobre el array.

4

Actualizar stock en pantalla: el stock cambia sin importar cuántos lotes se afectaron. Recarga el resumen de stock como antes — no necesitas agregarlo manualmente desde data.

Patrón — manejo de salidas y traslados

// ✅ Patrón robusto para POST /movements/exit y /movements/transfer
const response = await api.post('/movements/exit', payload)

if (response.success) {
  // data es siempre un array (1 o más movimientos según lotes afectados)
  const movements = response.data   // Array<Movement>

  // Cantidad total retirada (suma de los valores absolutos)
  const totalQty = movements.reduce((sum, m) => sum + Math.abs(m.quantity), 0)

  // Lotes afectados (para mostrar trazabilidad en UI)
  const lots = movements.map(m => ({
    lotNumber:  m.batch_lot_number,
    quantity:   Math.abs(m.quantity),
    movementId: m.id,
  }))

  // ID del primer movimiento (si necesitas referenciar uno solo)
  const primaryId = movements[0].id

  showToast(`Salida registrada: ${totalQty} unidades`)
  refreshStockSummary(payload.warehouse_id, payload.product_id)
}
